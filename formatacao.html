Java Formatar Texto

Mostrar 9.5 como 9,50, alinhar uma tabela de alunos em colunas, escrever R$ 1.234,56: tudo isso é formatar. O Java tem um "molde" de texto, com lacunas como %d e %.2f, que é usado em três lugares: String.format, printf e formatted. E tem um detalhe que pega todo brasileiro: o idioma do computador muda a vírgula e o ponto.

Você vai aprender
  • Usar String.format, System.out.printf e "…".formatted(…).
  • Os especificadores: %s %d %f %.2f %5d %-10s %05d %,d %x %e %n %%.
  • Por que, num computador em português, %.2f mostra vírgula, e como forçar o ponto com Locale.US.
  • Montar tabelas alinhadas.
  • Formatar dinheiro com NumberFormat e o espaço "invisível" de R$ 1.234,56.
  • As exceções de formato mais comuns.

A ideia antes do código

Pense num formulário de papel: "Eu, ________, de ___ anos, declaro…". O texto fixo já está impresso; você só preenche as lacunas. Cada lacuna tem um formato esperado: o nome é texto, a idade é número.

No Java, o formulário é uma String com especificadores de formato (as lacunas), que começam com %: "%s tem %d anos". Depois do formulário, você passa os valores, na mesma ordem das lacunas.

Três formas de usar o mesmo molde

FormaO que fazExemplo
String.format(molde, valores…)Devolve uma String prontaString s = String.format("%d anos", 29);
System.out.printf(molde, valores…)Mostra na tela (não pula linha sozinho)System.out.printf("%d anos%n", 29);
molde.formatted(valores…) Java 15+Igual ao String.format, escrito a partir do moldeString s = "%d anos".formatted(29);

O printf vem da linguagem C ("print formatted", imprimir formatado). System.out.format é um sinônimo dele. As três formas entendem exatamente os mesmos especificadores.

String nome = "Ana";
int idade = 29;
System.out.printf("%s tem %d anos%n", nome, idade);
"%s tem %d anos%n"
O molde. Tem três especificadores.
%s
Lacuna para texto (string). Recebe o primeiro valor, nome.
%d
Lacuna para número inteiro (decimal, "na base 10"). Recebe o segundo valor, idade.
%n
Quebra de linha (new line). O printf não pula linha sozinho como o println. Não consome valor nenhum.
nome, idade
Os valores, na ordem das lacunas.

Os especificadores

Um programa que mostra os mais usados, rodado na máquina da Ana (em português do Brasil):

        String nome = "Ana";

        double nota = 9.5;
        System.out.printf("%s tem %d anos%n", nome, idade);
        System.out.printf("Nota: %f%n", nota);

        System.out.printf("Nota: %.0f%n", nota);
        System.out.printf("Pi: %.4f%n", Math.PI);
        System.out.printf("[%5d]%n", 42);
        System.out.printf("[%-5d]%n", 42);
        System.out.printf("[%05d]%n", 42);
        System.out.printf("[%10s]%n", nome);
        System.out.printf("[%-10s]%n", nome);

A anatomia de um especificador

Todos seguem a mesma ordem: %, depois (opcionais) as opções, a largura e a precisão, e por fim a conversão (a letra):

%
Começo da lacuna.
- 0 , +
Opções (flags): - alinha à esquerda; 0 completa com zeros; , separa milhares; + mostra o sinal também nos positivos.
10
Largura mínima, em caracteres.
.2
Precisão: casas decimais (em %f) ou máximo de caracteres (em %s: %.3s mostra só 3 letras).
f
A conversão: s, d, f, x, e, b, c…

Exemplo completo: %,10.2f = separador de milhar, largura 10, duas casas, número decimal.

Vírgula ou ponto? O locale

Repare de novo na saída acima: %.2f mostrou 9,50, com vírgula, mas o println(nota) da última linha mostrou 9.5, com ponto. Por quê?

O String.format, o printf e o formatted seguem o locale (pronuncia-se "lôu-quél"): a configuração de idioma e país do computador. A máquina da Ana está em pt_BR (português do Brasil), onde a vírgula separa os decimais e o ponto separa os milhares. Já o println e o + com texto ignoram o locale e usam sempre o ponto, o formato do próprio Java.

import java.util.Locale;

public class Main {
    public static void main(String[] args) {
        double valor = 1234567.891;
        System.out.println(Locale.getDefault());
        System.out.println(String.format("%,.2f", valor));
        System.out.println(String.format(Locale.US, "%,.2f", valor));
        System.out.println(String.format(Locale.GERMANY, "%,.2f", valor));
        System.out.println(String.format(Locale.FRANCE, "%,.2f", valor));
        System.out.println("%.2f".formatted(valor));
        System.out.println(valor);
    }
}

Locale.getDefault()
O locale padrão da JVM, que ela pega do sistema: pt_BR (idioma pt, país BR). A classe Locale fica em java.util, por isso o import.
String.format("%,.2f", valor)
Sem dizer o locale: usa o padrão. 1.234.567,89.
String.format(Locale.US, …)
Passando um locale como primeiro argumento, ele vale só para esta chamada. Estados Unidos: 1,234,567.89, o contrário do Brasil.
Locale.GERMANY, Locale.FRANCE
A Alemanha usa o mesmo formato do Brasil; a França separa milhares com um espaço (um espaço especial, que não quebra a linha).
"%.2f".formatted(valor)
O formatted usa sempre o locale padrão: não tem versão com Locale.
println(valor)
Sem formatação nenhuma: o formato do Java, com ponto e todas as casas.
O mesmo programa, saídas diferentes

Um programa com printf("%.2f") mostra 9,50 no computador da Ana e 9.50 num servidor configurado em inglês. Quando o texto vai ser lido por pessoas, isso é bom: cada uma vê no formato do seu país. Quando o texto vai ser lido por outro programa (um arquivo CSV, um JSON, um número que será convertido de volta com Double.parseDouble, que só aceita ponto), use um locale fixo: String.format(Locale.US, …) ou Locale.ROOT (o locale "neutro").

Missão: no JShell, formate 3.14159 com duas casas usando ponto decimal, passando Locale.US para o String.format. (O JShell já importa java.util, então Locale funciona direto.) Experimente também sem o locale e veja a vírgula.

String.format(Locale.US, "%.2f", 3.14159)

Tabelas alinhadas

Com largura e alinhamento, a lista de alunos da Ana (a mesma do arquivo Documentos/alunos.csv) vira uma tabela. A regra prática: texto à esquerda (%-8s), números à direita (%5d, %5.1f), e a mesma largura no cabeçalho e nas linhas.

public class Main {
    public static void main(String[] args) {
        String[] nomes = {"Ana", "Bruno", "Carla", "Diego", "Elisa"};
        int[] idades = {29, 34, 22, 41, 27};
        String[] cidades = {"Recife", "Curitiba", "Salvador", "Manaus", "Porto Alegre"};
        double[] notas = {9.5, 7.0, 8.5, 6.0, 10.0};

        System.out.printf("%-8s %5s  %-14s %5s%n", "Nome", "Idade", "Cidade", "Nota");
        System.out.println("-".repeat(36));
        for (int i = 0; i < nomes.length; i++) {
            System.out.printf("%-8s %5d  %-14s %5.1f%n", nomes[i], idades[i], cidades[i], notas[i]);
        }
    }
}

$ java Main.java
Nome     Idade  Cidade          Nota
------------------------------------
Ana         29  Recife           9,5
Bruno       34  Curitiba         7,0
Carla       22  Salvador         8,5
Diego       41  Manaus           6,0
Elisa       27  Porto Alegre    10,0
"%-8s %5s %-14s %5s%n"
O cabeçalho usa %s em todas as colunas (são todos textos), mas com as mesmas larguras das linhas de dados, para as colunas baterem. "Idade" e "Nota" ficam à direita, em cima dos números.
"-".repeat(36)
Uma linha de 36 traços (a soma das larguras e dos espaços).
%5.1f
Nota com uma casa, ocupando 5 posições, alinhada à direita: 9,5 e 10,0 terminam na mesma coluna.

A largura é um mínimo: um nome com mais de 8 letras empurraria o resto da linha. Escolha larguras que caibam o maior valor. (Letras acentuadas contam como um caractere cada, então Maçã ocupa 4 posições, como esperado.)

Dinheiro: NumberFormat

Para moeda, em vez de montar "R$ " + String.format("%,.2f", …), use o NumberFormat (pacote java.text), que conhece o símbolo, a posição do sinal e as casas de cada moeda:

import java.text.NumberFormat;
import java.util.Locale;

public class Main {
    public static void main(String[] args) {
        double preco = 1234.56;
        NumberFormat real = NumberFormat.getCurrencyInstance(Locale.of("pt", "BR"));
        NumberFormat dolar = NumberFormat.getCurrencyInstance(Locale.US);
        NumberFormat porcento = NumberFormat.getPercentInstance();
        System.out.println(real.format(preco));
        System.out.println(dolar.format(preco));
        System.out.println(real.format(-5));
        System.out.println(porcento.format(0.256));
        String texto = real.format(preco);
        System.out.println(texto.equals("R$ 1.234,56"));
        System.out.println((int) texto.charAt(2));
    }
}

O espaço que não é espaço

As duas últimas linhas mostram uma surpresa: texto.equals("R$ 1.234,56") deu false, embora o texto pareça idêntico. O caractere na posição 2 (entre o $ e o 1) tem código 160, e não 32, o espaço comum. É o espaço não separável (non-breaking space, \u00A0), usado para o "R$" nunca ficar sozinho no fim de uma linha. Olhando os bytes com o od:

$ java Main.java | head -1 | od -c | head -2
0000000   R   $ 302 240   1   .   2   3   4   ,   5   6  \n
0000015

Os bytes 302 240 são esse caractere em UTF-8. Na tela, ele é igual a um espaço. Em testes e comparações, lembre-se dele: compare com "R$\u00A01.234,56" ou troque antes com texto.replace('\u00A0', ' ').

Dinheiro de verdade

O NumberFormat resolve a exibição. Para calcular com dinheiro, não use double: 0.1 + 0.2 não dá exatamente 0.3. Veja BigDecimal e Dinheiro (o NumberFormat formata BigDecimal também).

Quando dá errado

Os erros de formato não são pegos pelo javac: o molde é só uma String para ele. Eles aparecem na execução, como exceções. Repare que o texto antes da lacuna problemática chega a ser mostrado.

    public static void main(String[] args) {
        System.out.printf("%s tem %d anos%n", "Ana");

Resumo

  • Um molde com lacunas %… e os valores na ordem: String.format devolve, printf mostra, formatted (Java 15+) devolve.
  • Especificador = % + opções (- 0 , +) + largura + .precisão + letra (s d f x e b c). %n pula linha; %% é o próprio %.
  • A formatação segue o locale: em pt_BR, %.2f dá 9,50 e %,d dá 1.234.567. O println ignora o locale e usa ponto.
  • Para ponto fixo (arquivos, outros programas), passe Locale.US ou Locale.ROOT como primeiro argumento.
  • Tabelas: texto com %-Ns, números com %Nd/%N.2f, mesmas larguras no cabeçalho.
  • Moeda: NumberFormat.getCurrencyInstance(Locale.of("pt", "BR")) → R$ 1.234,56, com um espaço não separável (\u00A0) depois do R$.
  • Erros de formato são exceções em tempo de execução: MissingFormatArgumentException, IllegalFormatConversionException, UnknownFormatConversionException.
