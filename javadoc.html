Java Javadoc

Toda a documentação oficial do Java, aquela que explica o que faz cada método de String, Math ou ArrayList, foi escrita dentro do código-fonte, em comentários especiais, e transformada num site pela ferramenta javadoc. Você pode fazer o mesmo com as suas classes, e precisa saber ler esse formato para usar a biblioteca do Java.

Você vai aprender
  • A diferença entre //, /* */ e o comentário de documentação /** */.
  • Onde pôr um comentário de documentação e como escrevê-lo.
  • As tags @param, @return, @throws, @see, @since e os trechos {@code} e {@link}.
  • Gerar o site com javadoc -d doc … e entender os avisos (warning: no comment) e erros.
  • Os comentários em Markdown com /// (Java 23+).
  • Ler a documentação oficial da API.

A ideia: o manual que mora junto com a máquina

Pense no manual de um eletrodoméstico. Se ele fica numa gaveta separada, logo fica desatualizado: o fabricante muda um botão e esquece de mudar o manual. O Javadoc põe o manual colado em cada peça: o comentário fica logo acima do método que ele descreve. Quem muda o método vê o comentário na hora e o atualiza junto.

Esse comentário tem dois públicos:

  • Quem usa a sua classe (outra pessoa, ou você daqui a seis meses): lê o site gerado, ou a caixinha de ajuda que a IDE mostra ao passar o mouse sobre o método.
  • A ferramenta javadoc: lê os comentários e gera páginas HTML com índice, busca e links.

Três tipos de comentário

Você conheceu os comentários em Comentários. O terceiro tipo é o desta aula:

FormaNomePara quem
// …Comentário de linhaQuem lê o código: explica um detalhe da implementação
/* … */Comentário de blocoQuem lê o código: explicações mais longas
/** … */Comentário de documentação (Javadoc)Quem usa a classe: o que ela faz, não como

A única diferença visível é o segundo asterisco: /**. Para o compilador, os três são ignorados; para o javadoc, só o terceiro conta, e só quando está imediatamente antes de uma classe, um construtor, um método ou um atributo.

1. O primeiro comentário de documentação

/**
 * Coloca dinheiro na conta.
 *
 * @param valor quanto depositar; precisa ser maior que zero
 * @throws IllegalArgumentException se {@code valor} for zero ou negativo
 */
public void depositar(double valor) {
/**
Abre o comentário de documentação. Fica sozinho na linha.
* Coloca dinheiro na conta.
A descrição. A primeira frase (até o primeiro ponto) é o resumo, que aparece nas tabelas do site; capriche nela. Os * no começo das linhas são só enfeite (o javadoc os ignora), mas são o costume.
*
Uma linha vazia separa a descrição das tags.
@param valor …
Descreve o parâmetro valor: o nome tem de ser igual ao do método.
@throws IllegalArgumentException …
Descreve uma exceção que o método pode lançar, e quando.
{@code valor}
Mostra valor com fonte de código no site.
*/
Fecha o comentário, logo antes do método.
Descreva o que faz, não como faz

"Coloca dinheiro na conta" ajuda quem usa. "Soma valor ao atributo saldo com +=" não ajuda: isso está no código, e muda se a implementação mudar. Explique o comportamento visível: o que entra, o que sai, o que pode dar errado.

Dentro da descrição vale HTML simples: <p> para começar um parágrafo novo, <ul><li> para listas.

2. Gerar a documentação: javadoc -d

A Ana começou a documentar a classe Conta (a mesma de Testes com JUnit), mas só escreveu dois comentários: o da classe e o do depositar, ainda sem @param.

package br.com.ana.banco;

/**
 * Uma conta bancária simples, com titular e saldo.
 */
public class Conta {
    private final String titular;
    private double saldo;

    public Conta(String titular) {
        this.titular = titular;
    }

    public String getTitular() {
        return titular;
    }

    public double getSaldo() {
        return saldo;
    }

    /**
     * Coloca dinheiro na conta.
     */
    public void depositar(double valor) {
        if (valor <= 0) {
            throw new IllegalArgumentException("Valor inválido: " + valor);
        }
        saldo += valor;
    }

    public void sacar(double valor) {
        if (valor <= 0) {
            throw new IllegalArgumentException("Valor inválido: " + valor);
        }
        if (valor > saldo) {
            throw new IllegalStateException("Saldo insuficiente");
        }
        saldo -= valor;
    }
}

3. Comentários em Markdown: /// Java 23+

Desde o Java 23, você pode escrever a documentação em Markdown (o formato de texto simples usado em sites como o GitHub), começando cada linha com /// em vez de usar /** */. Código vai entre crases, em vez de {@code}; as tags @param e @return continuam iguais:

/// Formata valores em reais.
///
/// Exemplo: `Moeda.formatar(4.5)` devolve `R$ 4,50`.
public class Moeda {

    /// Cria o utilitário (não é preciso: os métodos são estáticos).
    public Moeda() {
    }

    /// Formata um valor com duas casas decimais.
    ///
    /// @param valor o valor em reais
    /// @return o texto formatado, como `R$ 4,50`
    public static String formatar(double valor) {
        return String.format("R$ %.2f", valor);
    }
}

$ javadoc -quiet -d doc Moeda.java
$ echo $?
0
$ grep -o "<code>R\$ 4,50</code>" doc/Moeda.html | head -2
<code>R$ 4,50</code>                « as crases viraram código no HTML
<code>R$ 4,50</code>

Em código anterior ao Java 23 (e na maior parte do código que você vai ler), o formato é o /** */; os dois funcionam no JDK 25. Escolha um e use sempre o mesmo no projeto.

Como navegar

  1. Use a caixa de busca (Search) no alto: digite String e escolha java.lang.String; ou digite o nome de um método, como charAt.
  2. Na página da classe, leia a descrição do topo (muitas trazem exemplos de uso).
  3. Vá ao Method Summary, a tabela com todos os métodos e o resumo de cada um. É o lugar para descobrir "existe um método que faz…?".
  4. Clique no método para ver os detalhes: parâmetros, retorno, exceções.
  5. Repare em Methods declared in class …: os métodos herdados (veja Herança) aparecem listados separadamente.

A organização é por módulo (java.base tem o essencial; veja Módulos), depois pacote (java.lang, java.util…), depois classe. A documentação está em inglês; o tradutor do navegador ajuda, mas os nomes de métodos e as tags (Parameters, Returns) você logo reconhece. Nas IDEs, o mesmo texto aparece ao passar o mouse sobre um método (ou com Ctrl+Q no IntelliJ).

Quando dá errado

error: @param name not found

A Ana mudou o nome no @param do sacar para quantia, mas o parâmetro continua se chamando valor:

     * @param quantia quanto sacar; precisa ser maior que zero
              ^
src/br/com/ana/banco/Conta.java:64: warning: no @param for valor
    public void sacar(double valor) {
                ^
1 error
1 warning

1

O que aconteceu: o nome do @param tem de ser igual ao do parâmetro. Este é um erro (não um aviso): o código de saída é 1. Acontece muito quando se renomeia um parâmetro e se esquece o comentário. Como resolver: deixe os nomes iguais.

warning: use of default constructor, which does not provide a comment 
$ javadoc -quiet -d doc Moeda.java
Moeda.java:4: warning: use of default constructor, which does not provide a comment
public class Moeda {
       ^
1 warning

O que aconteceu: a classe não declara construtor, então o Java cria um construtor público vazio (o "construtor padrão", veja Construtores), que entra na documentação sem descrição. Como resolver: declare o construtor e documente-o (como na Moeda com ///), ou torne-o private se a classe só tem métodos static.

O comentário não aparece no site

O que aconteceu: uma destas três: começou com /* (um asterisco só); há algo entre o comentário e o método (um import, outro comentário… anotações como @Override podem ficar no meio); ou o item não é public/protected. Como resolver: confira o /** e a posição. Para incluir itens privados, use javadoc -private.

Missão final: documente o método sacar com uma frase de resumo, @param valor e @throws IllegalStateException dizendo quando ela acontece. O programa deve continuar mostrando Saldo insuficiente.

public class Main {
    static double saldo = 100.0;

    static void sacar(double valor) {
        if (valor > saldo) {
            throw new IllegalStateException("Saldo insuficiente");
        }
        saldo -= valor;
    }

    public static void main(String[] args) {
        try {
            sacar(500.0);
        } catch (IllegalStateException e) {
            System.out.println(e.getMessage());
        }
    }
}

Resumo

  • /** */ logo antes de uma classe, construtor, método ou atributo é um comentário de documentação; // e /* */ não entram na documentação.
  • A primeira frase é o resumo. Depois, as tags: @param (uma por parâmetro, com o nome exato), @return, @throws, @see, @since. No texto: {@code} e {@link}.
  • Descreva o que o método faz para quem usa, não como foi implementado.
  • javadoc -d doc Arquivos.java gera o site; warning: no comment e no @param são avisos (o site sai com buracos); @param name not found é erro.
  • Por padrão, só itens public e protected são documentados.
  • Java 23+: comentários em Markdown com ///.
  • A documentação oficial (docs.oracle.com/en/java/javase/25/docs/api/) é feita do mesmo jeito: leia a assinatura, a descrição, Parameters, Returns e Throws.
