Projeto Calculadora

O primeiro projeto do guia: uma calculadora que roda no terminal. Ela pergunta a operação e os dois números, mostra o resultado e continua até você digitar sair. Parece simples, e é de propósito: o desafio não é a conta, é fazer o programa não quebrar quando alguém digita "abc", divide por zero ou escolhe uma operação que não existe.

Você vai praticar
  • Ler números e texto do teclado com Scanner.
  • Escolher a conta com o switch com setas.
  • Organizar o código em métodos com parâmetros e retorno.
  • Validar a entrada com hasNextDouble (e ver o que acontece sem validar).
  • Tratar a divisão por zero de um double.
  • Repetir tudo com while, break e continue.

Vamos chegar lá em seis etapas:

  1. Ler dois números e somar (Scanner, nextDouble).
  2. Escolher a operação (switch com setas).
  3. Organizar em métodos (calcular, lerNumero, operacaoValida).
  4. Validar o que foi digitado (hasNextDouble).
  5. Não dividir por zero.
  6. Repetir até "sair" (while, break, continue).

Etapa 1 · Ler dois números e somar

O começo de toda calculadora: pedir dois números e mostrar a soma. Para ler do teclado, o Java usa um Scanner (em inglês, "leitor", "escâner"), um objeto que lê o que você digita e transforma em números ou texto.

import java.util.Scanner;

public class Calculadora {
    public static void main(String[] args) {
        Scanner entrada = new Scanner(System.in);
        System.out.println("=== Calculadora da Ana ===");

        System.out.print("Primeiro número: ");
        double a = entrada.nextDouble();
        System.out.print("Segundo número: ");
        double b = entrada.nextDouble();

        double soma = a + b;
        System.out.println(a + " + " + b + " = " + soma);
    }
}

Etapa 2 · Escolher a operação

Agora a calculadora pergunta qual conta fazer. A operação é um texto ("+", "-"…), lido com entrada.next(), que devolve a próxima "palavra" digitada. Para escolher a conta, um switch com setas: ele compara o texto com cada case e devolve o valor da seta escolhida.

import java.util.Scanner;

public class Calculadora {
    public static void main(String[] args) {
        Scanner entrada = new Scanner(System.in);
        System.out.println("=== Calculadora da Ana ===");

        System.out.print("Primeiro número: ");
        double a = entrada.nextDouble();
        System.out.print("Operação (+, -, *, /): ");
        String op = entrada.next();
        System.out.print("Segundo número: ");
        double b = entrada.nextDouble();

        double resultado = switch (op) {
            case "+" -> a + b;
            case "-" -> a - b;
            case "*" -> a * b;
            case "/" -> a / b;
            default -> {
                System.out.println("Operação desconhecida: " + op);
                yield 0;
            }
        };
        System.out.println(a + " " + op + " " + b + " = " + resultado);
    }
}
double resultado =
O switch aqui é uma expressão: ele produz um valor, que vai para resultado.
switch (op)
Olha o valor de op e procura o case igual. Com String, a comparação é pelo conteúdo do texto.
case "+" -> a + b;
Se op for "+", o valor do switch é a + b. A seta -> não "cai" no próximo case: não precisa de break.
default -> { … yield 0; }
Qualquer outro texto. Como aqui há duas instruções, elas vão entre chaves, e yield ("render", "entregar") diz qual valor o switch devolve.
$ java Calculadora.java
=== Calculadora da Ana ===
Primeiro número: 10

Segundo número: 4
10.0 * 4.0 = 40.0
$ java Calculadora.java

Primeiro número: 10
Operação (+, -, *, /): /
Segundo número: 4
10.0 / 4.0 = 2.5
$ java Calculadora.java

Operação (+, -, *, /): x
Segundo número: 4                         « a operação é inválida, mas ele pede o número mesmo assim
Operação desconhecida: x
10.0 x 4.0 = 0.0                          « e ainda mostra um resultado falso

A divisão 10.0 / 4.0 deu 2.5, e não 2, porque os dois números são double (divisão inteira só acontece entre inteiros; veja Operadores Aritméticos). A terceira execução mostra um defeito: com a operação x, o programa pede o segundo número à toa e mostra 0.0 como se fosse uma resposta. A etapa 3 conserta isso.

Quando dá errado: esqueci o default

Este código tem um erro de propósito.

        double resultado = switch (op) {
            case "+" -> a + b;
            case "-" -> a - b;
        };

$ javac Calculadora.java
Calculadora.java:5: error: the switch expression does not cover all possible input values
        double resultado = switch (op) {
                           ^
1 error

"A expressão switch não cobre todos os valores possíveis." Um switch que devolve um valor precisa ter resposta para qualquer texto, e uma String pode ser qualquer coisa. Acrescente um default.

Etapa 3 · Organizar em métodos

O main está ficando comprido. Vamos separar o programa em métodos: blocos com nome, cada um com uma tarefa. É como numa cozinha: um cozinheiro corta, outro cozinha, outro monta o prato. Ao mesmo tempo, mudamos a ordem: a operação vem primeiro, e se ela for inválida o programa avisa e para, sem pedir os números à toa.

import java.util.Scanner;

public class Calculadora {
    public static void main(String[] args) {
        Scanner entrada = new Scanner(System.in);
        System.out.println("=== Calculadora da Ana ===");

        System.out.print("Operação (+, -, *, /): ");
        String op = entrada.next();
        if (!operacaoValida(op)) {
            System.out.println("Operação desconhecida: " + op);
            return;
        }
        double a = lerNumero(entrada, "Primeiro número: ");
        double b = lerNumero(entrada, "Segundo número: ");
        double resultado = calcular(a, op, b);
        System.out.println(a + " " + op + " " + b + " = " + resultado);
    }

    static double lerNumero(Scanner entrada, String pergunta) {
        System.out.print(pergunta);
        return entrada.nextDouble();
    }

    static boolean operacaoValida(String op) {
        return switch (op) {
            case "+", "-", "*", "/" -> true;
            default -> false;
        };
    }

    static double calcular(double a, String op, double b) {
        return switch (op) {
            case "+" -> a + b;
            case "-" -> a - b;
            case "*" -> a * b;
            case "/" -> a / b;
            default -> throw new IllegalArgumentException("Operação desconhecida: " + op);
        };
    }
}
MétodoRecebeDevolveTarefa
lerNumeroo Scanner e a perguntadoubleMostra a pergunta e lê um número. Assim não repetimos print + nextDouble duas vezes.
operacaoValidaa operaçãobooleantrue se for uma das quatro. case "+", "-", "*", "/" junta vários valores no mesmo case.
calcularos dois números e a operaçãodoubleFaz a conta. Só faz conta: não lê teclado nem escreve na tela. Isso deixa o método fácil de testar e de reaproveitar.
static
O método pertence à classe, e por isso o main (que também é static) pode chamá-lo direto. Veja static.
double
O tipo do valor devolvido (retorno).
calcular(double a, String op, double b)
O nome e os parâmetros: as "entradas" do método.
return switch (op) { … };
Devolve o valor que o switch produzir.
default -> throw new IllegalArgumentException(…)
Se alguém chamar calcular com uma operação inválida, o método lança uma exceção (avisa que recebeu um argumento ilegal) em vez de inventar um resultado. Veja throw e throws.

No main, o ! em !operacaoValida(op) quer dizer "não" (operadores lógicos), e o return sozinho encerra o main, ou seja, o programa.

Etapa 4 · Validar o que foi digitado

Hoje, se alguém digita uma palavra no lugar do número, a calculadora "explode":

$ java Calculadora.java
=== Calculadora da Ana ===
Operação (+, -, *, /): +
Primeiro número: abc
Exception in thread "main" java.util.InputMismatchException
	at java.base/java.util.Scanner.throwFor(Scanner.java:977)
	at java.base/java.util.Scanner.next(Scanner.java:1632)
	at java.base/java.util.Scanner.nextDouble(Scanner.java:2603)
	at Calculadora.lerNumero(Calculadora.java:22)
	at Calculadora.main(Calculadora.java:14)

Leia o stack trace (a "pilha de chamadas") de baixo para cima: o main, na linha 14, chamou o lerNumero, que na linha 22 chamou o nextDouble, que lançou a exceção. As linhas com java.base/ são do próprio Java; as que importam para você são as do seu arquivo.

A solução é perguntar antes de ler. O método hasNextDouble() ("tem um próximo double?") olha o que foi digitado sem consumir e devolve true se aquilo é um número válido. Só mudamos o método lerNumero; o resto do programa fica igual:

    static double lerNumero(Scanner entrada, String pergunta) {
        System.out.print(pergunta);
        while (!entrada.hasNextDouble()) {
            String lixo = entrada.next();
            System.out.println("\"" + lixo + "\" não é um número. Tente de novo.");
            System.out.print(pergunta);
        }
        return entrada.nextDouble();
    }
while (!entrada.hasNextDouble())
"Enquanto o que foi digitado não for um número…" O hasNextDouble espera a pessoa digitar, se for preciso, mas não tira nada da entrada.
String lixo = entrada.next();
Tira a palavra inválida da entrada. Esta linha é essencial: sem ela, o hasNextDouble olharia para o mesmo "abc" para sempre, num laço infinito.
"\"" + lixo + "\" …"
\" é uma aspa dentro do texto (caracteres especiais).
return entrada.nextDouble();
Quando o laço termina, com certeza há um número esperando: agora é seguro ler.

Uma família de métodos "has"

Para cada nextXxx existe um hasNextXxx: hasNextInt(), hasNextLine(), hasNext()… Use-os sempre que a entrada vier de uma pessoa. A tabela completa está em Ler do Teclado (Scanner).

Etapa 5 · Não dividir por zero

Na escola você aprendeu que não existe divisão por zero. O Java, com double, não reclama: ele responde com valores especiais.

$ java Calculadora.java
=== Calculadora da Ana ===
Operação (+, -, *, /): /
Primeiro número: 10
Segundo número: 0
10.0 / 0.0 = Infinity                     « "infinito"
$ java Calculadora.java
=== Calculadora da Ana ===
Operação (+, -, *, /): /
Primeiro número: -10
Segundo número: 0
-10.0 / 0.0 = -Infinity
$ java Calculadora.java
=== Calculadora da Ana ===
Operação (+, -, *, /): /
Primeiro número: 0
Segundo número: 0
0.0 / 0.0 = NaN                           « Not a Number: "não é um número"

Com números inteiros (int), a mesma conta não dá infinito: dá erro. Compare no JShell:

$ jshell
|  Welcome to JShell -- Version 25.0.4.1
|  For an introduction type: /help intro

jshell> 10 / 0
|  Exception java.lang.ArithmeticException: / by zero
|        at (#1:1)

jshell> 10.0 / 0
$2 ==> Infinity

Para uma calculadora de gente, "Infinity" não serve. Vamos conferir o divisor antes de calcular. No main, logo depois de ler o segundo número:

        double b = lerNumero(entrada, "Segundo número: ");
        if (op.equals("/") && b == 0) {
            System.out.println("Não dá para dividir por zero.");
            return;

Resumo

  • Um Scanner(System.in) lê o teclado; nextDouble() lê números (com vírgula em pt_BR) e next() lê uma palavra.
  • O switch com setas devolve um valor e precisa de default quando o tipo é String.
  • Métodos pequenos, cada um com uma tarefa, deixam o main fácil de ler.
  • hasNextDouble() confere antes de ler; o next() descarta o que não serve.
  • Divisão de double por zero dá Infinity ou NaN; de int, dá ArithmeticException. Confira o divisor antes.
  • while (true) + break + continue fazem o "menu que repete".
