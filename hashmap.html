Java HashMap

Numa lista, você encontra as coisas pela posição (o 1º, o 2º…). Mas muitas vezes você quer encontrar pelo nome: o preço do café, a nota da Ana, a capital de Pernambuco. Para isso existe o mapa (Map), que liga cada chave a um valor, e a sua implementação mais usada, o HashMap.

Você vai aprender
  • O que são chave e valor, e como criar um HashMap.
  • put, get (e o null de uma chave que não existe), getOrDefault, containsKey, remove.
  • Percorrer um mapa com keySet, values e entrySet.
  • Contar palavras (frequência) de três jeitos, até o merge.
  • Por que a ordem não é garantida, e o LinkedHashMap, que guarda a ordem.
  • Mapas prontos e imutáveis com Map.of.

A ideia: um dicionário

Num dicionário de papel, você não procura "a palavra número 3.512": você procura pela palavra e encontra o significado. A palavra é a chave (key); o significado é o valor (value). Um mapa funciona igual:

  chave       valor
  "pão"    →  0.75
  "leite"  →  5.49
  "café"   →  18.90

Duas regras definem um mapa:

  • Cada chave aparece uma vez só. Não existem dois "pão" na tabela. Se você guardar "pão" de novo, o valor antigo é substituído.
  • Valores podem se repetir. O pão e a banana podem custar o mesmo.

Em outras linguagens isso se chama "dicionário" (Python), "objeto" ou "tabela associativa". No Java, a interface é Map<K, V>: K é o tipo da chave (key) e V, o do valor (value).

Criar, guardar e buscar: put e get

import java.util.HashMap;
import java.util.Map;

public class Main {
    public static void main(String[] args) {
        Map<String, Double> precos = new HashMap<>();
        precos.put("pão", 0.75);
        precos.put("leite", 5.49);
        precos.put("café", 18.90);
        System.out.println(precos);
        System.out.println("Tamanho: " + precos.size());

        System.out.println("Preço do leite: " + precos.get("leite"));
        System.out.println("Preço do queijo: " + precos.get("queijo"));

        Double antigo = precos.put("leite", 5.99);
        System.out.println("O leite custava " + antigo + ", agora " + precos.get("leite"));
        System.out.println(precos);
    }
}
Map<String, Double>
"Um mapa de String para Double": a chave é um texto (o produto), o valor é um número decimal (o preço). Lembre: coleções guardam objetos, por isso Double e não double (veja Wrappers).
new HashMap<>()
Cria o mapa vazio. A variável é a interface Map; o objeto, um HashMap (veja programar para a interface).
precos.put("pão", 0.75)
put = colocar. Liga a chave "pão" ao valor 0.75. Se a chave já existia, troca o valor e devolve o antigo.
precos.get("leite")
get = pegar. Devolve o valor ligado à chave, ou null se a chave não existe.
precos.size()
Quantos pares chave-valor existem.

Quatro coisas para reparar:

  1. O mapa se imprime entre chaves { }, com cada par no formato chave=valor.
  2. A ordem não é a da inserção: o leite apareceu antes do pão. Isso tem explicação, e você vai vê-la mais abaixo.
  3. get("queijo") não deu erro: devolveu null, o "nada" do Java. Isso é cômodo, mas perigoso, como mostra o cenário de erro no fim da aula.
  4. O segundo put("leite", …) não criou outro leite: o mapa continua com 3 pares, e o put devolveu o preço antigo.

Perguntar e remover

import java.util.HashMap;
import java.util.Map;

        estoque.put("banana", 30);
        estoque.put("uva", 0);

        System.out.println("getOrDefault(\"kiwi\", 0): " + estoque.getOrDefault("kiwi", 0));
        System.out.println("getOrDefault(\"maçã\", 0): " + estoque.getOrDefault("maçã", 0));
        System.out.println("containsKey(\"uva\"): " + estoque.containsKey("uva"));

        System.out.println("depois de putIfAbsent: " + estoque);

MétodoTraduçãoO que faz
getOrDefault(k, padrao)"pegar ou o padrão"O valor de k; se k não existe, devolve padrao em vez de null.
containsKey(k)"contém a chave"true se a chave existe. Rápido.
containsValue(v)"contém o valor"true se algum par tem esse valor. Lento: olha todos.

containsKey ou get(k) != null?

Os dois costumam dar a mesma resposta, mas não sempre: um HashMap aceita null como valor (put("x", null)). Aí get("x") devolve null mesmo com a chave existindo. Para a pergunta "a chave existe?", use containsKey.

Percorrer um mapa

Um mapa não é uma Collection, então não dá para fazer um for-each direto nele. Mas ele oferece três "visões" que são coleções:

VisãoTipoContém
keySet()Set<K>só as chaves (um conjunto: sem repetidos)
values()Collection<V>só os valores (podem se repetir)
entrySet()Set<Map.Entry<K, V>>os pares; cada par (entry, "entrada") tem getKey() e getValue()
import java.util.HashMap;
import java.util.Map;

public class Main {
    public static void main(String[] args) {
        Map<String, Double> notas = new HashMap<>();
        notas.put("Ana", 9.5);
        notas.put("Bruno", 7.0);
        notas.put("Carla", 8.25);

        System.out.println("keySet(): " + notas.keySet());
        System.out.println("values(): " + notas.values());
        System.out.println("entrySet(): " + notas.entrySet());

        for (String nome : notas.keySet()) {
            System.out.println("Aluno: " + nome);
        }

        double soma = 0;
        for (double n : notas.values()) {
            soma += n;
        }
        System.out.println("Média: " + soma / notas.size());

        for (Map.Entry<String, Double> par : notas.entrySet()) {
            System.out.println(par.getKey() + " tirou " + par.getValue());
        }

        notas.forEach((nome, nota) -> System.out.println(nome + " -> " + nota));
    }
}

$ java Main

values(): [7.0, 8.25, 9.5]
entrySet(): [Bruno=7.0, Carla=8.25, Ana=9.5]

Aluno: Carla
Aluno: Ana
Média: 8.25

Carla tirou 8.25

Ana -> 9.5
for (String nome : notas.keySet())
"Para cada nome no conjunto de chaves". Use quando só precisa das chaves.
for (double n : notas.values())
"Para cada valor". Bom para somar, achar o maior… O Java converte cada Double em double sozinho.
Map.Entry<String, Double> par
Entry é um tipo que mora "dentro" de Map (por isso Map.Entry). Cada par tem getKey() e getValue().
notas.forEach((nome, nota) -> …)
A forma curta: uma lambda que recebe a chave e o valor.

Quando precisar da chave e do valor, prefira entrySet() ou forEach: fazer for (String k : keySet()) e chamar get(k) dentro do laço funciona, mas busca cada chave duas vezes.

Contar coisas: a frequência das palavras

O uso mais clássico de um mapa: contar quantas vezes cada coisa aparece. A chave é a coisa (a palavra), o valor é a contagem. Veja três formas, da mais explicada à mais curta. As três dão o mesmo resultado:

import java.util.HashMap;
import java.util.Map;

public class Main {
    public static void main(String[] args) {
        String frase = "o rato roeu a roupa do rei de roma e o rato fugiu";
        String[] palavras = frase.split(" ");

        // Forma 1: if com containsKey
        Map<String, Integer> f1 = new HashMap<>();
        for (String p : palavras) {
            if (f1.containsKey(p)) {
                f1.put(p, f1.get(p) + 1);
            } else {
                f1.put(p, 1);
            }
        }

        // Forma 2: getOrDefault
        Map<String, Integer> f2 = new HashMap<>();
        for (String p : palavras) {
            f2.put(p, f2.getOrDefault(p, 0) + 1);
        }

        // Forma 3: merge
        Map<String, Integer> f3 = new HashMap<>();
        for (String p : palavras) {
            f3.merge(p, 1, Integer::sum);
        }

        System.out.println(f1);
        System.out.println(f2);
        System.out.println(f3);
        System.out.println("\"rato\" aparece " + f3.get("rato") + " vezes");
    }
}
FormaComo se lê
1. if (f1.containsKey(p))"Se a palavra já está no mapa, some 1 ao que estava; senão, comece com 1."
2. f2.getOrDefault(p, 0) + 1"Pegue a contagem atual (ou 0, se é a primeira vez) e some 1."
3. f3.merge(p, 1, Integer::sum)merge = mesclar. "Se a palavra não existe, guarde 1; se existe, junte o valor velho com o 1 usando a soma." Integer::sum é uma referência de método: o mesmo que (velho, novo) -> velho + novo.
$ javac Main.java
$ java Main
{fugiu=1, a=1, de=1, roupa=1, roma=1, e=1, rei=1, roeu=1, do=1, o=2, rato=2}
{fugiu=1, a=1, de=1, roupa=1, roma=1, e=1, rei=1, roeu=1, do=1, o=2, rato=2}
{fugiu=1, de=1, a=1, roupa=1, roma=1, e=1, rei=1, roeu=1, do=1, rato=2, o=2}
"rato" aparece 2 vezes

As contagens são iguais nas três: o e rato com 2, o resto com 1. Mas olhe com atenção a terceira linha: de e a trocaram de lugar, e rato e o também. Os mesmos dados, no mesmo tipo de mapa, saíram em outra ordem só porque foram colocados com outro método. É o assunto da próxima seção.

A ordem não é garantida

Por que o HashMap embaralha? Pense num gaveteiro com gavetas numeradas. Para guardar uma chave, o HashMap calcula um número a partir dela (o hash code, uma espécie de "impressão digital" numérica; veja A Classe Object) e usa esse número para escolher a gaveta. Para achar a chave depois, faz a mesma conta e vai direto à gaveta certa, sem olhar as outras. É por isso que o get é tão rápido, mesmo com milhões de chaves.

O preço disso: ao imprimir, o HashMap percorre as gavetas na ordem das gavetas, que não tem nada a ver com a ordem em que você guardou nem com a ordem alfabética. Veja as mesmas sete frutas em três mapas diferentes:

import java.util.HashMap;
import java.util.LinkedHashMap;
import java.util.Map;
import java.util.TreeMap;

public class Main {
    public static void main(String[] args) {
        String[] frutas = {"uva", "banana", "maçã", "kiwi", "abacaxi", "laranja", "pera"};

        Map<String, Integer> hash = new HashMap<>();
        Map<String, Integer> linked = new LinkedHashMap<>();
        Map<String, Integer> tree = new TreeMap<>();
        for (int i = 0; i < frutas.length; i++) {
            hash.put(frutas[i], i + 1);
            linked.put(frutas[i], i + 1);
            tree.put(frutas[i], i + 1);
        }
        System.out.println("HashMap:       " + hash);
        System.out.println("LinkedHashMap: " + linked);
        System.out.println("TreeMap:       " + tree);
    }
}

$ javac Main.java
$ java Main
HashMap:       {banana=2, pera=7, uva=1, kiwi=4, maçã=3, abacaxi=5, laranja=6}   « ordem das "gavetas"
LinkedHashMap: {uva=1, banana=2, maçã=3, kiwi=4, abacaxi=5, laranja=6, pera=7}   « ordem de inserção
TreeMap:       {abacaxi=5, banana=2, kiwi=4, laranja=6, maçã=3, pera=7, uva=1}   « ordem das chaves (A→Z)

O número depois de cada fruta é a ordem em que ela foi colocada. No HashMap saiu 2, 7, 1, 4, 3, 5, 6: nenhuma ordem que faça sentido para nós. E essa ordem pode mudar se o mapa crescer, se os dados forem colocados com outro método (como você viu com o merge) ou numa outra versão do Java.

Nunca escreva um programa que dependa da ordem de um HashMap

Se o seu programa "funciona" porque o HashMap por acaso imprime na ordem certa, ele pode quebrar amanhã. Quando a ordem importa, escolha o mapa certo:

MapaOrdem ao percorrerQuando usar
HashMapNenhuma garantidaO padrão: você só busca por chave e a ordem não importa.
LinkedHashMapA de inserção (quem entrou primeiro sai primeiro)Um cardápio, um relatório, um formulário: a ordem em que você colocou é a que deve sair.
TreeMapChaves em ordem crescente (alfabética, numérica)Listagens ordenadas, "a primeira chave depois de X". Veja TreeMap e TreeSet.

Trocar é fácil: como a variável é do tipo Map, basta mudar o new. O LinkedHashMap funciona exatamente como o HashMap, com os mesmos métodos, só lembrando a ordem; é um pouco mais pesado, porque mantém também uma "corrente" ligando os pares na ordem de chegada.

Mapas prontos: Map.of

Como List.of, o Map.of cria um mapa pronto e imutável, passando chave, valor, chave, valor…

import java.util.Map;

public class Main {
    public static void main(String[] args) {
        Map<String, String> capitais = Map.of(
            "PE", "Recife",
            "RN", "Natal",
            "PB", "João Pessoa"
        );
        System.out.println(capitais.get("PE"));
        System.out.println(capitais.size());
        capitais.put("CE", "Fortaleza");
    }
}

Ler funciona; put dá UnsupportedOperationException. Para um mapa que pode mudar, copie: new HashMap<>(Map.of(…)). O Map.of aceita até 10 pares; para mais, existe Map.ofEntries(Map.entry("PE", "Recife"), …).

E a ordem? No Map.of ela é embaralhada de propósito, e muda a cada execução, justamente para ninguém depender dela. O mesmo programa rodado três vezes:

Quando dá errado

NullPointerException ao guardar o get num int

Este código tem um erro de propósito.

import java.util.HashMap;
import java.util.Map;

public class Main {
    public static void main(String[] args) {
        Map<String, Integer> idades = new HashMap<>();
        idades.put("Ana", 29);
        int idade = idades.get("Zeca");
        System.out.println(idade);
    }
}

$ javac Main.java
$ java Main
Exception in thread "main" java.lang.NullPointerException: Cannot invoke "java.lang.Integer.intValue()" because the return value of "java.util.Map.get(Object)" is null
	at Main.main(Main.java:8)

O que quer dizer: "não posso chamar Integer.intValue() porque o valor devolvido por Map.get é null". O Zeca não está no mapa, então get devolveu null. Para guardar num int, o Java tenta desembrulhar o Integer (chamando intValue()), e não existe nada para desembrulhar.

Como consertar: use idades.getOrDefault("Zeca", 0), confira antes com containsKey, ou guarde num Integer e teste if (idade != null).

IllegalArgumentException: duplicate key no Map.of

Este código tem um erro de propósito.

import java.util.Map;

public class Main {
    public static void main(String[] args) {
        Map<String, String> capitais = Map.of("PE", "Recife", "PE", "Olinda");
    }
}

$ javac Main.java
$ java Main
Exception in thread "main" java.lang.IllegalArgumentException: duplicate key: PE
	at java.base/java.util.ImmutableCollections$MapN.<init>(ImmutableCollections.java:1440)
	at java.base/java.util.Map.of(Map.java:1384)
	at Main.main(Main.java:5)

O que quer dizer: "argumento ilegal: chave duplicada: PE". Com put, repetir uma chave substitui o valor em silêncio; o Map.of é mais rigoroso e recusa, porque chave repetida ali é quase sempre erro de digitação.

Como consertar: remova a chave repetida.

A saída saiu "embaralhada"

O que aconteceu: não é erro: o HashMap não guarda ordem. Veja A ordem não é garantida.

Como consertar: LinkedHashMap para a ordem de inserção; TreeMap para ordem alfabética.

Resumo

  • Um Map<K, V> liga cada chave (única) a um valor. HashMap é a implementação padrão.
  • put guarda (e substitui), get busca (e devolve null se não achar), getOrDefault evita o null.
  • containsKey pergunta, remove tira, putIfAbsent só coloca se não existe.
  • Percorra com keySet(), values(), entrySet() ou forEach((k, v) -> …).
  • Para contar: mapa.merge(chave, 1, Integer::sum).
  • HashMap não garante ordem; LinkedHashMap guarda a de inserção; TreeMap ordena as chaves.
  • Map.of cria mapas imutáveis, recusa chaves repetidas e embaralha a ordem a cada execução.
  • int x = mapa.get(chaveQueNaoExiste) dá NullPointerException.
