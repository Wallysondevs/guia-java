Projeto: Agenda de Contatos

Uma agenda que cadastra, lista, busca e remove contatos e, o mais importante, lembra deles: tudo fica gravado num arquivo de texto e volta na próxima vez que o programa abrir. É o primeiro projeto do guia que guarda dados de verdade, e por isso o primeiro em que você vai cuidar de arquivos que podem estar faltando ou estragados.

Você vai praticar
  • Representar um contato com um record.
  • Guardar vários contatos numa lista (ArrayList).
  • Montar um menu com switch com setas e ler linhas inteiras com nextLine.
  • Buscar com métodos de String (toLowerCase, contains) e remover com segurança.
  • Salvar e carregar com Files e Path (Ler e Escrever Arquivos), tratando IOException com try e catch.

Etapa 1 · O contato

Um contato tem nome, telefone e e-mail: três textos que andam sempre juntos. Em vez de três variáveis soltas, criamos um tipo novo, Contato, com um record ("registro"): uma classe feita só para carregar dados, escrita numa linha.

public class Agenda {

    record Contato(String nome, String telefone, String email) {
    }

    public static void main(String[] args) {
        Contato bruno = new Contato("Bruno Lima", "(11) 91234-5678", "bruno@exemplo.com");
        Contato carla = new Contato("Carla Dias", "(21) 99876-5432", "carla@exemplo.com");

        System.out.println(bruno);
        System.out.println(carla.nome() + " - " + carla.telefone());
    }
}

Quando dá errado: tentar mudar um contato

Este código tem um erro de propósito.

        Contato bruno = new Contato("Bruno Lima", "(11) 91234-5678", "bruno@exemplo.com");
        bruno.telefone = "(11) 90000-0000";

$ java Agenda.java
Agenda.java:8: error: cannot assign a value to final variable telefone
        bruno.telefone = "(11) 90000-0000";
             ^
1 error
error: compilation failed

"Não dá para atribuir um valor à variável final telefone." Os componentes de um record são final: um contato, depois de criado, não muda (ele é imutável). Para "trocar o telefone", crie um contato novo com o telefone novo e coloque-o no lugar do antigo. A última linha, error: compilation failed, é do lançador java: no modo arquivo-fonte, ele compila antes de rodar e avisa que a compilação falhou.

Etapa 2 · A lista de contatos

Uma agenda tem muitos contatos, e não sabemos quantos. Um array tem tamanho fixo; uma lista (ArrayList) cresce sozinha a cada add. Criamos também o método listar, que mostra os contatos numerados.

import java.util.ArrayList;
import java.util.List;

public class Agenda {

    record Contato(String nome, String telefone, String email) {
    }

    public static void main(String[] args) {
        List<Contato> contatos = new ArrayList<>();
        contatos.add(new Contato("Bruno Lima", "(11) 91234-5678", "bruno@exemplo.com"));
        contatos.add(new Contato("Carla Dias", "(21) 99876-5432", "carla@exemplo.com"));
        contatos.add(new Contato("Diego Rocha", "(31) 98888-1111", "diego@exemplo.com"));

        listar(contatos);
    }

    static void listar(List<Contato> contatos) {
        if (contatos.isEmpty()) {
            System.out.println("Nenhum contato.");
            return;
        }
        for (int i = 0; i < contatos.size(); i++) {
            Contato c = contatos.get(i);
            System.out.println((i + 1) + ". " + c.nome() + " | " + c.telefone() + " | " + c.email());
        }
        System.out.println(contatos.size() + " contato(s).");
    }
}
TrechoO que faz
List<Contato> contatosUma lista que só aceita Contato. O <Contato> é o "tipo dos itens" (generics). Declaramos como List (a interface) e criamos um ArrayList (a implementação).
new ArrayList<>()Lista vazia. O <> vazio ("diamante") repete o tipo da esquerda.
contatos.add(…)Põe um contato no fim da lista.
contatos.isEmpty()true se a lista não tem nada.
contatos.size() e contatos.get(i)Quantos itens há, e o item da posição i (começando em 0). Por isso mostramos i + 1.

Etapa 3 · O menu e o cadastro

Agora a lista começa vazia e quem cadastra é a pessoa, por um menu. O formato é o mesmo da calculadora (while (true) + switch), com uma diferença importante: aqui lemos linhas inteiras com nextLine(), porque nomes têm espaço.

import java.util.ArrayList;
import java.util.List;
import java.util.Scanner;

public class Agenda {

    record Contato(String nome, String telefone, String email) {
    }

    public static void main(String[] args) {
        Scanner entrada = new Scanner(System.in);
        List<Contato> contatos = new ArrayList<>();
        System.out.println("=== Agenda da Ana ===");

        while (true) {
            System.out.println();
            System.out.println("1) Listar  2) Adicionar  0) Sair");
            System.out.print("Opção: ");
            String opcao = entrada.nextLine().trim();
            switch (opcao) {
                case "1" -> listar(contatos);
                case "2" -> adicionar(entrada, contatos);
                case "0" -> {
                    System.out.println("Até logo!");
                    return;
                }
                default -> System.out.println("Opção inválida: " + opcao);
            }
        }
    }

    static void listar(List<Contato> contatos) {
        if (contatos.isEmpty()) {
            System.out.println("Nenhum contato.");
            return;
        }
        for (int i = 0; i < contatos.size(); i++) {
            Contato c = contatos.get(i);
            System.out.println((i + 1) + ". " + c.nome() + " | " + c.telefone() + " | " + c.email());
        }
        System.out.println(contatos.size() + " contato(s).");
    }

    static void adicionar(Scanner entrada, List<Contato> contatos) {
        System.out.print("Nome: ");
        String nome = entrada.nextLine().trim();
        if (nome.isEmpty()) {
            System.out.println("O nome não pode ficar vazio.");
            return;
        }
        System.out.print("Telefone: ");
        String telefone = entrada.nextLine().trim();
        System.out.print("E-mail: ");
        String email = entrada.nextLine().trim();
        contatos.add(new Contato(nome, telefone, email));
        System.out.println("Adicionado: " + nome);
    }
}
entrada.nextLine()
Lê tudo até o Enter, com espaços: Bruno Lima inteiro. O next() leria só Bruno.
.trim()
Corta espaços do começo e do fim (quem nunca digitou um espaço a mais?).
switch (opcao) { case "1" -> …; }
Aqui o switch é uma instrução (não devolve valor): cada seta só chama um método. A opção é lida como texto, então "abc" cai no default sem exceção nenhuma.
case "0" -> { …; return; }
Duas instruções, então vão entre chaves. O return sai do main e encerra o programa.
if (nome.isEmpty())
Recusa nome vazio: quem aperta Enter sem digitar não cria um contato "fantasma".

Por que não usar nextInt() para a opção?

Misturar nextInt() com nextLine() é a armadilha mais famosa do Scanner: o nextInt() lê o número, mas deixa o Enter na entrada, e o nextLine() seguinte lê essa "linha vazia" na hora, pulando a pergunta do nome. Lendo tudo com nextLine(), o problema não existe. Veja a explicação completa em Ler do Teclado (Scanner).

Etapa 4 · Buscar e remover

Duas opções novas no menu: 3) Buscar e 4) Remover. A busca encontra contatos por parte do nome, sem ligar para maiúsculas; a remoção apaga pelo nome completo.

    static void buscar(Scanner entrada, List<Contato> contatos) {
        System.out.print("Buscar por: ");
        String termo = entrada.nextLine().trim().toLowerCase();
        int achados = 0;
        for (Contato c : contatos) {
            if (c.nome().toLowerCase().contains(termo)) {
                System.out.println("- " + c.nome() + " | " + c.telefone() + " | " + c.email());
                achados++;
            }
        }
        if (achados == 0) {
            System.out.println("Nenhum contato com \"" + termo + "\".");
        }
    }

    static void remover(Scanner entrada, List<Contato> contatos) {
        System.out.print("Nome para remover: ");
        String nome = entrada.nextLine().trim();
        for (Contato c : contatos) {
            if (c.nome().equalsIgnoreCase(nome)) {
                contatos.remove(c);
                System.out.println("Removido: " + c.nome());
                return;
            }
        }
        System.out.println("Não encontrei \"" + nome + "\".");
    }
TrechoO que faz
termo.toLowerCase() e c.nome().toLowerCase()Passa os dois lados para minúsculas, para que "carl" ache "Carla". Comparar só um lado não funcionaria.
.contains(termo)true se o termo aparece em qualquer lugar do nome.
for (Contato c : contatos)O for-each: "para cada contato c da lista". Não precisa de índice.
equalsIgnoreCase(nome)Igualdade exata, ignorando maiúsculas: "bruno lima" remove "Bruno Lima".
contatos.remove(c) seguido de returnTira o contato da lista e sai do método na hora. O return é obrigatório aqui; veja o cenário abaixo.

Quando dá errado: remover dentro do for-each e continuar

A Ana quis remover todos os contatos que começam com "Carl" e tirou o return:

Este código tem um erro de propósito.

        for (Contato c : contatos) {
            if (c.nome().startsWith("Carl")) {
                contatos.remove(c);
            }
        }

$ java Agenda.java
Exception in thread "main" java.util.ConcurrentModificationException
	at java.base/java.util.ArrayList$Itr.checkForComodification(ArrayList.java:1096)
	at java.base/java.util.ArrayList$Itr.next(ArrayList.java:1050)
	at Agenda.main(Agenda.java:15)

"Modificação concorrente": a lista mudou enquanto o for-each andava por ela, e o Java parou tudo para não pular ou repetir itens. Com o return logo depois do remove, o laço nunca dá o próximo passo, e por isso a etapa 4 funciona. Para remover vários de uma vez, use contatos.removeIf(c -> c.nome().startsWith("Carl")) (com uma lambda) ou um Iterator.

E se eu quiser o record num arquivo separado?

Em programas maiores, cada tipo vai no seu arquivo: Contato.java com public record Contato(…) { … }, e Agenda.java com o resto. Desde o Java 22, java Agenda.java encontra sozinho o Contato.java na mesma pasta. O próximo projeto é organizado assim.

Desafios extras

  1. Sem nomes repetidos. Em adicionar, recuse um nome que já existe (ignorando maiúsculas).
  2. Lista em ordem alfabética. Antes de listar, ordene: contatos.sort(Comparator.comparing(Contato::nome)) (veja Comparable e Comparator).

  5. Buscar também pelo telefone. Faça a busca olhar nome ou telefone.

public class Agenda {

    record Contato(String nome, String telefone, String email) {
        String paraLinha() {
            return nome + ";" + telefone + ";" + email;
        }
    }

    static final Path ARQUIVO = Path.of("contatos.txt");

    public static void main(String[] args) {
        Scanner entrada = new Scanner(System.in);
        List<Contato> contatos = carregar();
        System.out.println("=== Agenda da Ana === " + contatos.size() + " contato(s) carregado(s)");

        while (true) {
            System.out.println();

            System.out.print("Opção: ");
            String opcao = entrada.nextLine().trim();
            switch (opcao) {
                case "1" -> listar(contatos);
                case "2" -> adicionar(entrada, contatos);
                case "3" -> buscar(entrada, contatos);
                case "4" -> remover(entrada, contatos);
                case "0" -> {
                    System.out.println("Até logo!");
                    return;
                }
                default -> System.out.println("Opção inválida: " + opcao);
            }
        }
    }

Resumo

  • Um record junta dados relacionados e ganha construtor, nome(), toString e equals de graça; os componentes não mudam.
  • ArrayList cresce sozinho; add, get, size, isEmpty, remove.
  • Com nextLine() + trim() em tudo, nomes com espaço funcionam e o menu não "pula" perguntas.
  • Remover dentro de um for-each só é seguro se você sair do laço logo depois.
  • Files.write grava uma lista de linhas; Files.readAllLines lê de volta. IOException precisa de try/catch (ou throws).
  • split(";", -1) mantém campos vazios; confira o tamanho antes de usar as partes.
