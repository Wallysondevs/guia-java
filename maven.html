Java Maven

Na aula de JAR, a Ana compilou, montou o classpath e criou o JAR à mão, com vários comandos. Num projeto de verdade, com dezenas de classes, testes e bibliotecas, isso vira um pesadelo. O Maven é a ferramenta que faz todo esse trabalho com um comando: mvn package.

Você vai aprender
  • O que é o Maven e quais problemas ele resolve (dependências e build padronizado).
  • Criar um projeto com mvn archetype:generate e, também, escrevendo o pom.xml à mão.
  • O pom.xml mínimo para Java 25, linha por linha.
  • A estrutura de pastas padrão (src/main/java, src/test/java).
  • mvn compile, mvn test, mvn package, mvn clean e a pasta target/.
  • O repositório local ~/.m2/repository e como adicionar uma biblioteca.
  • Ler um BUILD FAILURE: erro de compilação, dependência inexistente, pasta errada.

Os exemplos rodam na máquina fictícia da Ana, com Maven 3.10.0 e JDK 25. As saídas do Maven são longas; quando um trecho for repetitivo (como centenas de linhas de download), ele aparece encurtado com … e um aviso.

A ideia: uma receita de bolo que a cozinha entende

Pense numa padaria. Cada confeiteiro tinha o seu jeito de organizar a cozinha, e cada receita dizia "pegue a farinha no armário da esquerda, depois ligue o forno…". Quando alguém novo chegava, levava dias para entender a cozinha do outro.

O Maven é uma cozinha padronizada: a farinha está sempre no mesmo lugar, o forno sempre liga do mesmo jeito. A sua receita (o arquivo pom.xml) só precisa dizer o que é diferente no seu bolo: o nome, a versão, os ingredientes comprados prontos (as dependências). Isso tem até nome: convention over configuration, "convenção em vez de configuração".

O Maven resolve dois problemas:

ProblemaSem MavenCom Maven
Dependências (bibliotecas de outras pessoas)Procurar o JAR na internet, baixar, baixar também os JARs de que ele precisa, montar o -cp à mãoEscrever 5 linhas no pom.xml; o Maven baixa tudo, inclusive as dependências das dependências
Build (compilar, testar, empacotar)javac -d … -cp …, rodar os testes, jar cfe …, cada projeto de um jeitomvn package, igual em qualquer projeto Maven do mundo

Maven é uma palavra do iídiche que quer dizer "especialista, quem acumula conhecimento". O comando é mvn. É a ferramenta de build mais usada em Java; a outra grande é o Gradle.

1. Instalar e conferir

No laboratório da Ana, o Maven já está instalado em /opt/maven. No Ubuntu/Debian, você instalaria com sudo apt install maven (pode vir uma versão mais antiga) ou baixando o .tar.gz do site maven.apache.org e pondo a pasta bin no PATH, do mesmo jeito que o JDK em Instalar no Linux. O Maven precisa de um JDK instalado. Confira:

$ mvn -version

2. Criar um projeto com mvn archetype:generate

Um arquétipo (archetype, "modelo original") é um molde de projeto. O Maven tem um para "aplicativo simples", o maven-archetype-quickstart. Normalmente o comando faz perguntas; com -DinteractiveMode=false ele usa o que você passar e não pergunta nada:

$ mvn archetype:generate -DgroupId=br.com.ana -DartifactId=loja -DarchetypeArtifactId=maven-archetype-quickstart -DarchetypeVersion=1.5 -DjavaCompilerVersion=25 -DinteractiveMode=false
mvn archetype:generate
Rode o plugin archetype, tarefa (goal, "objetivo") generate. Quase tudo no Maven é feito por plugins.
-DgroupId=br.com.ana
O grupo: quem fez o projeto, normalmente um domínio ao contrário (como os pacotes). Cada -Dnome=valor passa uma configuração.
-DartifactId=loja
O artefato: o nome do projeto. Vira o nome da pasta e do JAR.
-DarchetypeArtifactId=maven-archetype-quickstart
Qual molde usar.
-DarchetypeVersion=1.5
A versão do molde. Sem isso, o Maven usa a versão 1.0, de 2006, que gera um projeto com JUnit 3.
-DjavaCompilerVersion=25
Para qual versão do Java compilar (o molde usa 17 se você não disser).
-DinteractiveMode=false
Não fazer perguntas.

3. O pom.xml mínimo, escrito à mão

POM é Project Object Model, "modelo do projeto". É um arquivo XML: texto com marcações entre < >, em que cada <nome> abre um item e </nome> fecha (parecido com HTML). A Ana criou um projeto novo, caixa, só com este arquivo:

<?xml version="1.0" encoding="UTF-8"?>
<project xmlns="http://maven.apache.org/POM/4.0.0"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="http://maven.apache.org/POM/4.0.0 https://maven.apache.org/xsd/maven-4.0.0.xsd">
    <modelVersion>4.0.0</modelVersion>

    <groupId>br.com.ana</groupId>
    <artifactId>caixa</artifactId>
    <version>1.0</version>

    <properties>
        <maven.compiler.release>25</maven.compiler.release>
        <project.build.sourceEncoding>UTF-8</project.build.sourceEncoding>
    </properties>
</project>
LinhaO que faz
<?xml version="1.0" encoding="UTF-8"?>"Este é um arquivo XML, em UTF-8." Fica sempre na primeira linha.
<project xmlns=… xsi:schemaLocation=…>Abre o projeto. Os endereços dizem "este XML segue o formato de POM 4.0.0"; servem para o editor completar e conferir o arquivo. Copie como está.
<modelVersion>4.0.0</modelVersion>A versão do formato do POM. É sempre 4.0.0 no Maven 3.
<groupId>br.com.ana</groupId>Quem fez: o grupo.
<artifactId>caixa</artifactId>O nome do projeto.
<version>1.0</version>A versão do seu projeto. Junto com o grupo e o nome, forma as coordenadas br.com.ana:caixa:1.0, o "endereço" único do projeto no mundo Maven.
<properties>Configurações em forma de "nome = valor".
<maven.compiler.release>25</…>Compilar para o Java 25 (vira o javac --release 25).
<project.build.sourceEncoding>UTF-8</…>Os .java estão em UTF-8 (para acentos como em "pão" não virarem lixo).
</project>Fecha o projeto.

Só isso. Não há uma linha dizendo onde está o código, como compilar, nem como gerar o JAR: tudo segue a convenção. O 1.0-SNAPSHOT que o arquétipo usou é uma versão "em andamento" (snapshot = "foto do momento"): o -SNAPSHOT avisa que aquela versão ainda muda.

A estrutura de pastas padrão

O código vai em src/main/java, seguindo as pastas do pacote. A Ana criou o caixa da aula de JAR, agora com printf:

$ mkdir -p caixa/src/main/java/br/com/ana/caixa && cd caixa
package br.com.ana.caixa;

public class Caixa {
    public static void main(String[] args) {
        double total = 0;
        for (String a : args) {
            total += Double.parseDouble(a);
        }
        System.out.printf("Itens: %d%n", args.length);
        System.out.printf("Total: R$ %.2f%n", total);
    }
}
PastaO que vai nela
pom.xmlA receita, na raiz do projeto
src/main/java/O código do programa (.java), em pastas por pacote
src/main/resources/Arquivos que não são código e vão junto no JAR (textos, configurações, imagens)
src/test/java/Os testes automatizados (não vão para o JAR)
src/test/resources/Arquivos usados só pelos testes
target/Tudo o que o Maven gera. Nunca edite; pode apagar quando quiser

Missão: esta é a classe Caixa do projeto (sem o package, porque o editor do guia usa um arquivo só). Ela recebe os preços como argumentos. Acrescente uma linha que mostre a média dos preços, no mesmo formato: Média: R$ 5,58.

        double total = 0;
        for (String a : args) {
            total += Double.parseDouble(a);
        }
        System.out.printf("Itens: %d%n", args.length);
        System.out.printf("Total: R$ %.2f%n", total);
    }
}

public class Main {
    public static void main(String[] args) {
        double total = 0;
        for (String a : args) {
            total += Double.parseDouble(a);
        }
        System.out.printf("Itens: %d%n", args.length);
        System.out.printf("Total: R$ %.2f%n", total);
        System.out.printf("Média: R$ %.2f%n", total / args.length);

}

4. O ciclo de vida: compile, test, package

O Maven organiza o build em fases, numa ordem fixa, como as etapas de uma linha de montagem. Quando você pede uma fase, ele roda todas as anteriores antes:

FaseO que faz
validateConfere se o pom.xml está certo
compileCompila src/main/java para target/classes
testCompila src/test/java e roda os testes
packageCria o JAR em target/
verifyVerificações extras de qualidade (se configuradas)
installCopia o JAR para o seu ~/.m2/repository, para outros projetos seus usarem
deployPublica o JAR num repositório remoto (para a equipe ou o mundo)

Então mvn package = validar + compilar + testar + empacotar. Fora dessa fila existe o mvn clean, que apaga a pasta target.

JAR executável com o Maven

O JAR do Maven vem sem Main-Class, então dá o erro que você conhece da aula de JAR:

$ java -jar target/caixa-1.0.jar
nenhum atributo de manifesto principal em target/caixa-1.0.jar

Para o Maven escrever o Main-Class, configure o plugin maven-jar-plugin no pom.xml, depois de </properties>:

    <build>
        <plugins>
            <plugin>
                <groupId>org.apache.maven.plugins</groupId>
                <artifactId>maven-jar-plugin</artifactId>
                <version>3.5.1</version>
                <configuration>
                    <archive>
                        <manifest>
                            <mainClass>br.com.ana.caixa.Caixa</mainClass>
                        </manifest>
                    </archive>
                </configuration>
            </plugin>
        </plugins>
    </build>
<build><plugins><plugin>
"Quero mudar a configuração de um plugin do build."
groupId / artifactId / version
Qual plugin: o que cria o JAR, versão 3.5.1 (a que o Maven já estava usando).
<mainClass>
O nome completo da classe principal; vira o Main-Class do manifesto.

5. O repositório local ~/.m2/repository

Tudo o que o Maven baixa fica guardado na pasta .m2/repository dentro da sua pasta pessoal. É uma despensa: o Maven só vai ao "mercado" (o repositório Maven Central, em repo.maven.apache.org) quando falta algo. Por isso o primeiro build demora e os outros são rápidos.

6. Adicionar uma dependência

A Ana quer que o caixa gere um recibo em JSON, o formato de texto que sites e aplicativos usam para trocar dados. Escrever JSON à mão é chato e cheio de detalhes; existe uma biblioteca pequena do Google que faz isso, a Gson. A classe nova:

package br.com.ana.caixa;

import com.google.gson.Gson;
import java.util.List;

public class Recibo {
    record Item(String nome, double preco) {}

    public static void main(String[] args) {
        List<Item> itens = List.of(
                new Item("pão", 4.50),
                new Item("café", 10.0),
                new Item("leite", 2.25));
        Gson gson = new Gson();
        System.out.println(gson.toJson(itens));
    }
}

Resumo

  • O Maven baixa as dependências (e as dependências delas) e faz o build do mesmo jeito em qualquer projeto.
  • O pom.xml descreve o projeto: coordenadas groupId:artifactId:version, propriedades (como maven.compiler.release), dependências e plugins.
  • Convenção: código em src/main/java, testes em src/test/java, tudo o que é gerado em target/.
  • Fases: compile → test → package → install; pedir uma roda as anteriores. clean apaga o target.
  • Downloads ficam em ~/.m2/repository: o primeiro build é lento, os outros não.
  • Para ler um BUILD FAILURE, procure o primeiro [ERROR].
  • Could not resolve dependencies = coordenadas erradas ou sem internet; depois de corrigir, -U força nova tentativa.
