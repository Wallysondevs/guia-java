Java Exceções Comuns

Quando um programa Java quebra rodando, ele mostra uma exceção: o nome do problema, uma mensagem e a lista de onde aconteceu. Esta página reúne as exceções que você mais vai encontrar, cada uma com a mensagem real (todas provocadas de propósito num JDK 25), a causa e como evitar. Para entender o que é uma exceção e como tratá-la, veja O que são Exceções e try e catch.

Nesta página
  • Como ler uma exceção em 10 segundos.
  • A tabela das exceções comuns: quando, mensagem, como evitar, aula.
  • NullPointerException em detalhe (e o misterioso <local1>).
  • Errors: StackOverflowError e OutOfMemoryError.
  • Se o problema aparece antes de rodar, ao compilar, veja Erros do Compilador.

Como ler uma exceção

$ java Main.java
Exception in thread "main" java.lang.NumberFormatException: For input string: "vinte"
	at java.base/java.lang.NumberFormatException.forInputString(NumberFormatException.java:67)
	at java.base/java.lang.Integer.parseInt(Integer.java:565)
	at java.base/java.lang.Integer.parseInt(Integer.java:662)
	at Main.main(Main.java:3)
Exception in thread "main"
Uma exceção não tratada parou a thread principal (o seu main). O programa termina com código de saída 1.
java.lang.NumberFormatException
O tipo do problema, com o pacote na frente. É o nome que você procura na tabela abaixo.
For input string: "vinte"
A mensagem: o detalhe. Aqui, o texto que não virou número.
at java.base/…
Linhas de dentro do próprio Java. Quase sempre você pode pular.
at Main.main(Main.java:3)
A primeira linha do seu código, de cima para baixo: arquivo Main.java, linha 3. Comece por ela.

Essa lista de at … é o stack trace ("rastro da pilha"): quem chamou quem até o erro, do mais recente (em cima) para o mais antigo (embaixo).

Missão: o programa lê uma idade como texto e converte com Integer.parseInt. Com a entrada vinte, ele quebra com NumberFormatException. Capture a exceção e mostre Isso não é um número: vinte.

import java.util.Scanner;

public class Main {
    public static void main(String[] args) {
        Scanner entrada = new Scanner(System.in);
        System.out.print("Idade: ");
        String texto = entrada.nextLine();
        int idade = Integer.parseInt(texto);
        System.out.println("Ano que vem você terá " + (idade + 1));
    }
}

import java.util.Scanner;

public class Main {
    public static void main(String[] args) {
        Scanner entrada = new Scanner(System.in);
        System.out.print("Idade: ");
        String texto = entrada.nextLine();
        try {
            int idade = Integer.parseInt(texto);
            System.out.println("Ano que vem você terá " + (idade + 1));
        } catch (NumberFormatException e) {
            System.out.println("Isso não é um número: " + texto);
        }
    }
}

NullPointerException em detalhe

É a exceção mais famosa do Java. Desde o Java 14 (e por padrão desde o 15), a mensagem diz o que era null (são as helpful NullPointerExceptions). Com um atributo static que nunca recebeu valor:

$ java Main.java
Exception in thread "main" java.lang.NullPointerException: Cannot invoke "String.toUpperCase()" because "Main.apelido" is null
	at Main.main(Main.java:5)

"Não dá para chamar toUpperCase() porque Main.apelido é null." Com uma variável local, porém, aparece um nome estranho:

$ java Main.java
Exception in thread "main" java.lang.NullPointerException: Cannot invoke "String.length()" because "<local1>" is null
	at Main.main(Main.java:4)
$ javac -g Main.java
$ java Main
Exception in thread "main" java.lang.NullPointerException: Cannot invoke "String.length()" because "nome" is null
	at Main.main(Main.java:4)

<local1> é "a variável local número 1". Os nomes das variáveis locais só ficam guardados no .class quando você compila com javac -g (de debug, "depuração"); o java Main.java e o javac comum não guardam. Nos dois casos, a linha (Main.java:4) leva direto ao problema. O Maven e as IDEs já compilam com -g.

Missão: a classe Carrinho esqueceu de criar a lista, e o programa termina com NullPointerException. Rode, leia a mensagem e conserte inicializando o atributo, para mostrar Total de itens: 1.

import java.util.ArrayList;
import java.util.List;

public class Main {
    public static void main(String[] args) {
        Carrinho c = new Carrinho();
        c.adicionar("pão");
        System.out.println("Total de itens: " + c.total());
    }
}

class Carrinho {
    private List<String> itens;

    void adicionar(String item) {
        itens.add(item);
    }

    int total() {
        return itens.size();
    }
}

E quando o java nem acha a classe

Não é uma exceção do seu programa, mas aparece com a palavra "Exception": a classe pedida não existe (nome errado, pasta errada ou faltou compilar). A primeira parte vem em português, do lançador java:

$ java Olaa

Resumo

  • Leia: tipo da exceção, mensagem e a primeira linha at do seu arquivo.
  • Unchecked (RuntimeException) costuma ser defeito no código; checked (IOException…) é algo externo que você deve tratar.
  • Os campeões: NullPointerException, índices fora do limite, NumberFormatException, InputMismatchException, ConcurrentModificationException.
  • <local1> na mensagem do NPE = variável local de um código compilado sem -g.
