Java Palavras-chave

Palavras-chave são as palavras que o Java usa na própria gramática: class, if, return… Você não pode usá-las como nome de variável, método ou classe. Esta página lista todas as do Java 25, agrupadas pelo assunto, com o que cada uma faz, um exemplo curto e a aula onde ela é explicada.

Nesta página
  • As 51 palavras reservadas (50 palavras e o _), por assunto.
  • As 17 palavras contextuais (var, record, sealed, yield, when…), que só são especiais em certos lugares.
  • true, false e null, que não são palavras-chave, mas também são proibidas como nomes.
  • O que o javac diz quando você usa uma palavra-chave como nome.

Dois tipos de palavra-chave

Desde o Java 17, a especificação da linguagem separa as palavras-chave em dois grupos:

TipoRegraExemplo
ReservadaProibida como nome em qualquer lugar.int class = 3; não compila.
ContextualEspecial só em certas posições; no resto, é um nome comum. Assim o Java ganhou palavras novas (var, record…) sem quebrar programas antigos que já usavam esses nomes.int record = 16; compila; record Ponto(int x, int y) {} declara um record.

Prova no laboratório: todas estas variáveis têm nome de palavra contextual, e o programa compila e roda.

public class Main {
    public static void main(String[] args) {
        String var = "var é contextual";
        int record = 16;
        int yield = 14;
        int when = 21;
        int sealed = 17;
        var permits = "também";
        System.out.println(var + " " + record + " " + yield + " " + when + " " + sealed + " " + permits);
    }
}

$ java Main.java
var é contextual 16 14 21 17 também

Poder, pode. Mas não faça: um leitor vai estranhar uma variável chamada var.

Um programa que usa sealed, permits, record, when, var, yield e _ de uma vez:

import java.util.List;

public class Main {
    sealed interface Forma permits Circulo, Quadrado { }
    record Circulo(double raio) implements Forma { }
    record Quadrado(double lado) implements Forma { }

    static double area(Forma f) {
        return switch (f) {
            case Circulo c when c.raio() == 0 -> 0;
            case Circulo c -> Math.PI * c.raio() * c.raio();
            case Quadrado q -> q.lado() * q.lado();
        };
    }

    public static void main(String[] args) {
        var formas = List.of(new Circulo(1), new Quadrado(2), new Circulo(0));
        int contador = 0;
        for (Forma _ : formas) {
            contador++;
        }
        for (var f : formas) {
            System.out.println(f + " -> " + area(f));
        }
        String tamanho = switch (contador) {
            case 0 -> "nenhuma";
            default -> {
                String t = contador + " formas";
                yield t;
            }
        };
        System.out.println(tamanho);
    }
}

$ java Main.java
Circulo[raio=1.0] -> 3.141592653589793
Quadrado[lado=2.0] -> 4.0
Circulo[raio=0.0] -> 0.0
3 formas

true, false e null

Tecnicamente, não são palavras-chave: são literais (valores escritos direto no código), como 42 ou "Ana". Mas também são proibidos como nomes.

Quando dá errado

Uma palavra reservada como nome de variável

Estes códigos têm erros de propósito.

        int class = 3;
        System.out.println(class);

$ java Main.java
Main.java:3: error: not a statement
        int class = 3;
        ^
Main.java:3: error: ';' expected
        int class = 3;
           ^
Main.java:3: error: <identifier> expected
        int class = 3;
                 ^
Main.java:4: error: illegal start of expression
        System.out.println(class);
                           ^
Main.java:4: error: <identifier> expected
        System.out.println(class);
                                ^
5 errors
error: compilation failed

O javac não diz "class é palavra reservada": ele se perde e mostra uma cascata de erros (not a statement, ';' expected, <identifier> expected). Quando um erro aponta para uma linha que parece perfeita, confira se algum nome é palavra-chave. Com goto, const e até true, a mensagem é a mesma:

$ java Main.java
Main.java:3: error: not a statement
        int goto = 3;
        ^
Main.java:3: error: ';' expected
        int goto = 3;
           ^
2 errors
error: compilation failed
Uma palavra contextual onde ela é especial 
$ java Main.java
Main.java:2: error: 'var' not allowed here
    static class var { }
                 ^
  as of release 10, 'var' is a restricted type name and cannot be used for type declarations
1 error
error: compilation failed

"Desde a versão 10, var é um nome de tipo restrito e não pode ser usado para declarar tipos." Variável chamada var pode; classe chamada var, não. Com o _ é parecido: dá para declarar, mas não para ler:

$ java Main.java
Main.java:4: error: underscore not allowed here
        System.out.println(_);
                           ^
1 error
error: compilation failed

Missão: este programa não compila porque usa duas palavras reservadas como nomes de variável. Troque os nomes (por exemplo, novo e padrao) e faça-o mostrar Total: 30.

public class Main {
    public static void main(String[] args) {
        int new = 10;
        int default = 20;
        System.out.println("Total: " + (new + default));
    }
}

public class Main {
    public static void main(String[] args) {
        int novo = 10;
        int padrao = 20;
        System.out.println("Total: " + (novo + padrao));
    }
}

Resumo

  • 51 palavras reservadas (50 palavras e o _), proibidas como nomes em qualquer lugar; const e goto não fazem nada; strictfp está obsoleta.
  • 17 palavras contextuais (var, yield, record, sealed, non-sealed, permits, when e as 10 de módulos), especiais só em certas posições.
  • true, false e null são literais, também proibidos como nomes.
  • Usar uma palavra reservada como nome dá erros confusos (not a statement, ';' expected); desconfie dos nomes.
