Java ExecutorService

Na aula de Threads, você criou cada thread à mão com new Thread. Em programas de verdade quase ninguém faz isso: usa-se um ExecutorService ("serviço executor"), um time de threads prontas para trabalhar. Você entrega tarefas ao time, e ele cuida de quem faz o quê. De quebra, as tarefas podem devolver resultados.

Você vai aprender
  • O que é um pool de threads e como criar um com Executors.newFixedThreadPool.
  • Enviar tarefas com submit e buscar o resultado com Future.get.
  • Enviar uma lista inteira com invokeAll.
  • Encerrar o time: shutdown, awaitTermination e o executor em try-with-resources Java 19+; e o que acontece se você esquecer.
  • O básico de CompletableFuture: supplyAsync, thenApply e join.

Esta aula continua a de Threads e usa lambdas, generics e try-with-resources. Os exemplos rodaram no JDK 25 da máquina da Ana, na pasta ~/java.

A ideia antes do código

Pense numa central de entregas. A Ana não contrata um motoboy novo para cada pedido e o demite na volta: isso seria caro e lento. Ela tem uma equipe fixa de, digamos, dois motoboys, e um quadro de pedidos. Cada pedido novo vai para o quadro; quem estiver livre pega o próximo. No fim do dia, ela avisa: "não entram mais pedidos; terminem o que falta e podem ir".

  • A equipe fixa é o pool de threads (pool = "grupo", "reserva").
  • O quadro é a fila de tarefas.
  • O pedido é a tarefa: um Runnable (não devolve nada) ou um Callable (devolve um resultado).
  • O comprovante que a Ana recebe ao entregar um pedido ao quadro é o Future ("futuro"): com ele, ela pergunta depois "já ficou pronto? qual o resultado?".
  • "Não entram mais pedidos" é o shutdown().

1. Criar o time e enviar tarefas

import java.util.concurrent.ExecutorService;
import java.util.concurrent.Executors;
import java.util.concurrent.TimeUnit;

public class Main {
    public static void main(String[] args) throws InterruptedException {
        ExecutorService equipe = Executors.newFixedThreadPool(2);
        for (int i = 1; i <= 5; i++) {
            int pedido = i;
            equipe.submit(() -> {
                System.out.println(Thread.currentThread().getName() + " embalou o pedido " + pedido);
            });
        }
        equipe.shutdown();
        equipe.awaitTermination(10, TimeUnit.SECONDS);
        System.out.println("Expediente encerrado.");
    }
}

2. Tarefas que devolvem resultado: submit + Future.get

Se a lambda devolve um valor, ela é um Callable ("chamável"), e o submit entrega um Future com o resultado prometido. A Ana precisa consultar o estoque de três frutas num sistema lento, que demora 1 segundo por consulta:

import java.util.concurrent.ExecutorService;
import java.util.concurrent.Executors;
import java.util.concurrent.Future;

public class Main {
    static int consultarEstoque(String fruta) throws InterruptedException {
        Thread.sleep(1000); // finge que demora: consulta a um sistema lento
        return fruta.length() * 10;
    }

    public static void main(String[] args) throws Exception {
        ExecutorService equipe = Executors.newFixedThreadPool(3);
        long inicio = System.currentTimeMillis();

        Future<Integer> maca = equipe.submit(() -> consultarEstoque("maçã"));
        Future<Integer> banana = equipe.submit(() -> consultarEstoque("banana"));
        Future<Integer> uva = equipe.submit(() -> consultarEstoque("uva"));

        System.out.println("Pedidos enviados; esperando as respostas...");
        int total = maca.get() + banana.get() + uva.get();

        long ms = System.currentTimeMillis() - inicio;
        System.out.println("Estoque total: " + total);
        System.out.println("Tempo: cerca de " + ms / 100 * 100 + " ms");
        equipe.shutdown();
    }
}

E maca.get() ("pegar") espera o resultado ficar pronto e o devolve. As três consultas rodaram ao mesmo tempo, então o total levou cerca de 1 segundo, e não 3. Para conferir, a Ana trocou newFixedThreadPool(3) por newFixedThreadPool(1) (um motoboy só):

3. Uma lista de tarefas: invokeAll e o executor em try

Quando as tarefas já estão numa lista, invokeAll ("invocar todas") envia todas, espera todas terminarem e devolve a lista de Futures na mesma ordem. E desde o Java 19, o ExecutorService pode ficar num try-with-resources: ao sair do bloco, ele faz o shutdown e espera as tarefas sozinho.

import java.util.List;
import java.util.concurrent.Callable;
import java.util.concurrent.ExecutorService;
import java.util.concurrent.Executors;
import java.util.concurrent.Future;

public class Main {
    public static void main(String[] args) throws Exception {
        List<String> frutas = List.of("maçã", "banana", "uva", "kiwi");
        List<Callable<String>> tarefas = frutas.stream()
            .map(f -> (Callable<String>) () -> f.toUpperCase() + " (" + Thread.currentThread().getName() + ")")
            .toList();

        try (ExecutorService equipe = Executors.newFixedThreadPool(2)) {
            List<Future<String>> resultados = equipe.invokeAll(tarefas);
            for (Future<String> r : resultados) {
                System.out.println(r.get());
            }
        }
        System.out.println("Fim");
    }
}

$ javac Main.java && java Main
MAÇÃ (pool-1-thread-1)
BANANA (pool-1-thread-2)
UVA (pool-1-thread-2)
KIWI (pool-1-thread-2)
Fim

Os resultados saíram na ordem da lista de frutas, mesmo que as tarefas tenham terminado em outra ordem: quem garante isso é a lista de Futures. A coluna entre parênteses mostra qual thread fez cada uma (a thread-2 pegou três: estava livre antes). O .map(…) transforma cada fruta numa tarefa (veja streams); o (Callable<String>) diz ao compilador que tipo de lambda é aquela.

4. CompletableFuture: encadear passos

Com o Future comum, a única forma de usar o resultado é parar e esperar com get(). O CompletableFuture ("futuro completável") permite dizer o que fazer depois, como uma receita: "busque o preço; quando chegar, aplique o desconto; depois monte a etiqueta".

import java.util.concurrent.CompletableFuture;

public class Main {
    static double buscarPreco(String produto) {
        System.out.println("Buscando " + produto + " em " + Thread.currentThread().getName());
        return 50.0;
    }

    public static void main(String[] args) {
        CompletableFuture<String> etiqueta = CompletableFuture
            .supplyAsync(() -> buscarPreco("café"))
            .thenApply(preco -> preco * 0.9)
            .thenApply(preco -> "Café com desconto: R$ " + preco);

        System.out.println("main continua livre...");
        System.out.println(etiqueta.join());
    }
}

$ javac Main.java && java Main
main continua livre...
Buscando café em ForkJoinPool.commonPool-worker-1
Café com desconto: R$ 45.0

"Fornecer de forma assíncrona": roda a lambda em outra thread e promete o resultado. Sem um executor indicado, usa o pool comum do Java (ForkJoinPool.commonPool, como mostra a saída).
.thenApply(preco -> preco * 0.9)
"Depois, aplique": quando o preço chegar, transforma-o (10% de desconto). Devolve outro CompletableFuture, por isso dá para encadear.
.thenApply(preco -> "…" + preco)
Mais um passo: transforma o número em texto.
etiqueta.join()
"Juntar": espera o resultado final e o devolve, como o get(), mas sem exceção checked.

Repare que a main mostrou "continua livre" antes mesmo de a busca começar: montar a receita não trava ninguém. Só o join() espera. Outros métodos úteis:

import java.util.concurrent.CompletableFuture;

public class Main {
    public static void main(String[] args) {
        CompletableFuture<Double> cafe = CompletableFuture.supplyAsync(() -> 18.0);
        CompletableFuture<Double> pao = CompletableFuture.supplyAsync(() -> 6.5);
        double total = cafe.thenCombine(pao, Double::sum).join();
        System.out.println("Total do pedido: " + total);

        CompletableFuture<Integer> erro = CompletableFuture.supplyAsync(() -> 10 / 0);
        int r = erro.exceptionally(e -> {
            System.out.println("Deu problema: " + e.getMessage());
            return -1;
        }).join();
        System.out.println("Resultado: " + r);
    }
}

$ javac Main.java && java Main
Total do pedido: 24.5
Deu problema: java.lang.ArithmeticException: / by zero
Resultado: -1

thenCombine ("depois, combine") junta dois resultados independentes: café e pão foram buscados ao mesmo tempo e somados com Double::sum (uma referência de método). exceptionally ("em caso de exceção") dá um valor de reserva quando algum passo falha.

Quando dá errado

Esquecer o shutdown: o programa não termina

Este código tem um erro de propósito.
import java.util.concurrent.ExecutorService;
import java.util.concurrent.Executors;

public class Main {
    public static void main(String[] args) {
        ExecutorService equipe = Executors.newFixedThreadPool(2);
        equipe.submit(() -> System.out.println("Pedido embalado"));
        System.out.println("Fim do main");
    }
}

$ javac Main.java
$ timeout 5 java Main      « o timeout encerra o programa à força depois de 5 segundos
Fim do main
Pedido embalado
$ echo $?
124                        « 124 = o timeout teve de matar o programa

O que aconteceu: o trabalho terminou, mas as threads do pool continuaram vivas, esperando novos pedidos que nunca vão chegar. A JVM só termina quando as threads comuns acabam, então o programa ficaria parado para sempre (sem o timeout, você teria de apertar Ctrl+C). Conserto: shutdown() no fim, ou o executor num try-with-resources.

A tarefa lançou uma exceção: ExecutionException

Resumo

  • Um ExecutorService é um time de threads reaproveitáveis; você envia tarefas, não cria threads.
  • submit devolve um Future; get() espera o resultado (e lança ExecutionException se a tarefa falhou). invokeAll envia e espera uma lista inteira.
  • Sempre encerre: shutdown() + awaitTermination, ou try-with-resources Java 19+. Sem isso, o programa não termina.
  • CompletableFuture encadeia passos: supplyAsync → thenApply → join.
  • O ganho de tempo vem quando as tarefas esperam (3 consultas de 1 s: cerca de 1000 ms com 3 threads, 3000 ms com 1).
